蘑米虚拟伴游网页 Demo｜摄像头与手势修复版

本版本重点修复：
1. 摄像头页面按钮点击后不再只切换页面，会立即请求浏览器摄像头权限。
2. 摄像头视频只有在收到真实视频帧后才切换为“已连接”，失败时保留替代场景并显示具体排查提示。
3. 手势识别改为动态导入 MediaPipe Tasks Vision 官方 ESM 构建，避免依赖错误的 window.visionTasks 全局变量。
4. 手部模型初始化先尝试 GPU，失败后自动改用默认 CPU 推理。
5. 摄像头视频与镜像坐标同步，按手掌关键点计算中心并进行平滑跟随。
6. 增加真实手势触发：张开手掌、拇指和食指捏合，会触发蘑米不同的情绪反馈。
7. 支持鼠标拖动蘑米到指定位置、点击场景移动、摸头、休息以及制作明信片。拖动时会暂时停止手势跟随，防止位置互相抢写。

启动方式（Windows）：
1. 解压整个 ZIP，进入 virtual_pet_demo 文件夹。
2. 在文件夹地址栏输入 cmd 并回车。
3. 在命令行运行：python -m http.server 8000
   如果电脑使用 py 启动 Python，也可以运行：py -m http.server 8000
4. 浏览器打开：http://localhost:8000
5. 点击“遇见你的伙伴”，再点击“进入伴游视野”。网页会自动请求摄像头权限。
6. 允许权限后，摄像头会显示为实时背景；点击“开启手势跟随”，等待模型加载成功，再把手伸进摄像头视野。

摄像头无法打开时：
- 不要直接双击 index.html；摄像头通常要求 localhost 或 HTTPS 的安全环境。
- 检查浏览器地址栏旁的摄像头权限是否为“允许”。
- 关闭微信、会议软件、系统相机等可能占用摄像头的应用。
- 如提示没有设备，检查电脑是否有可用摄像头，或先使用页面模拟背景测试宠物交互。
- Chrome / Edge 首次打开权限弹窗时必须选择允许。若此前点了拒绝，需要从地址栏网站权限中重新开放。

手势识别无法加载时：
- 当前手势识别是真实 MediaPipe 手部关键点检测，不是鼠标模拟；首次使用需要网络加载模块、WASM 和模型文件。
- 网络需要能访问 jsDelivr CDN 与 Google 模型资源。校园网/代理/防火墙拦截时可能加载失败。
- 如果状态显示“手势模型加载失败”，页面下方会展示具体错误信息；可按提示检查网络，然后再次点击开启。
- 模型加载后，建议手部与背景有明显区分、室内光线充足，并让整只手进入摄像头画面。移动手掌可以控制蘑米位置；张开手掌或拇指与食指捏合可以触发反馈。
- 如果手势模型因网络无法加载，摄像头实时画面、鼠标点击移动、拖动和明信片仍可以单独使用。

真实功能与模拟边界：
- 摄像头：真实调用浏览器 getUserMedia，需设备、权限和安全访问环境支持。
- 手势：MediaPipe Hand Landmarker 实时检测关键点并控制宠物位置；首次运行依赖网络下载模型和 WASM。
- 张开手掌/捏合反馈：根据手部关键点距离与手指伸展状态判断，是轻量规则识别，并非复杂手语理解。
- 宠物：使用项目现有的透明 PNG 表情/动作帧，加上 CSS 动画；不是完整 Live2D 骨骼模型或 3D 模型。
- 明信片：将当前摄像头画面与蘑米合成到 Canvas 并导出 PNG；不是摄像头原始视频存档。
- 本项目没有真正接入 Rokid SDK、空间锚定或现实物体遮挡，因此是网页摄像头叠加演示，不等于完整空间 AR。
